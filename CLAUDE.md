# Tarkov Companion — working notes for Claude

Web + Windows desktop app for Escape from Tarkov players: quest tracking, interactive maps with quest overlays, and (desktop only) automatic quest completion from the game's own log files. The owner is a non-programmer: explain results in plain English, give exact commands, and keep commits self-contained.

## Commands
- `npm run dev` web dev server (5173) · `npm run dev:desktop` Electron with hot reload · `npm run build` web · `npm run dist:desktop` NSIS + portable exe into `release/`
- `npm test` vitest (parser tests) · `npm run scan:logs` prints what a log backfill finds · `npx tsc -b` typechecks app + node + electron configs · `npx oxlint`
- `npm run tiles:lighthouse` regenerates the RE3MR Lighthouse tiles (needs `assets-src/lighthouse/re3mrLighthouseVERT.png`, 23 MB download, see README)

## Data source: tarkov.dev JSON API (NOT GraphQL)
- Base `https://json.tarkov.dev`, catalog `/endpoints` (read first; `catalog.ts` asserts tasks/items/traders/maps exist). Docs: `/{gameMode}/{tasks|items|traders|maps}` with gameMode `regular` (PvP) or `pve`. GraphQL is deprecated and was down; never reintroduce it.
- Base docs contain translation keys, not English (`"657315dd… name"`). Always fetch `/{gameMode}/{endpoint}_en` and merge (`translate.ts`). traders doc: `data` keyed by id directly; maps/tasks/items under `data.maps|tasks|items`.
- Items doc is 17 MB raw (1.4 MB brotli); loaded lazily (`useItems`) and returns `{ items, playerLevels }`. Prices endpoint `/{gameMode}/prices/{itemId}` cached 5 min. Everything else staleTime 1 h, error retry every minute.
- Data quirks (current wipe): 282/515 tasks have minPlayerLevel 0, 296 have no quest prerequisites, 164 are gated by `otherRequirements` (story `globalVariable`/trader `dialogue`) we cannot track (shown as "Also requires"); `kappaRequired` true on only 13 tasks; zone ids repeat per map variant (dedupe by position); `exitName` on extract objectives matches `MapExtract.name`.

## Progress store (`src/store/progress.ts`, localStorage `tarkov-companion-progress`, v2)
`{ gameMode: 'regular'|'pve', profiles: { regular, pve } }`, each profile `{ playerLevel, faction: 'USEC'|'BEAR', completedTaskIds: Set, activeTaskIds: Set, failedTaskIds: Set }`. Sets are persisted through a replacer/reviver. **Any version bump needs a `migrate` function or zustand drops saved progress** (bitten once). Export/import JSON via Settings. Status rule: completed → available if level met and every prerequisite with status containing "complete" is done → else locked; "active"/"failed"-only requirements are treated as met.

## Maps
- Imagery per map = list of base layers (`mapConfig.ts`), each with an `affine` `[a,b,c,d,e,f]` (px = a·x+b·z+c, py = d·x+e·z+f in zoom-0 pixels) and `bounds`. tarkov.dev layers are derived from the vendored JSON (`affineFromTarkovDev`), extra layers live in `EXTRA_BASE_LAYERS`. Leaflet works in game coordinates: `L.latLng(z, x)`; the CRS applies the affine, so switching image = remounting MapContainer with a new CRS.
- Projection verified on Customs dorms. Interchange defaults to the SVG drawing (tiles are from 2023). Lighthouse uses RE3MR's render (CC BY-NC-SA 4.0, tiles gitignored); first-pass affine fitted from 15 extract icons, RMS ≈ 20 m; refine with `/dev/align` and paste "Copy transform" into `RE3MR_LIGHTHOUSE_AFFINE`. tarkov.dev has no satellite imagery for Lighthouse and its SVG is pre-1.1.5.
- MapViewer's container is `isolate` (own stacking context): Leaflet panes/controls use z-index 400–1000 and used to cover app dialogs (z-50) on the Maps page.
- Floors: tarkov.dev extents are per building (`{height, bounds:[[x,z],[x,z],label]}`); use `floorForPosition`, never height alone. Tile path uses `import.meta.env.BASE_URL` so it works from file:// in the desktop build.
- Overlay: `buildMapTasks` resolves zones/spawn points/named extracts per task; keys come only from the quest data (`requiredKeys`, task `neededKeys`); since 1.13.1 nothing is guessed from locked doors near an objective (owner: only accurate info, no guesses on maps or in the scanner). >200 markers switches to canvas circles. Checked tasks/colours/layer toggles persist in `mapOverlay.ts`. Geoman runs in opt-in mode (`L.PM.setOptIn(true)`, map created with `pmIgnore: false`, drawings flagged `__tcDrawing`): before that, `getGeomanLayers()` also returned every quest/extract marker and the drawing layer wiped them all on each map switch. tarkov.dev repeats some extract ids (Woods), so marker keys include the index.

## Desktop / log watcher (read-only, promised in README)
- Logs live in `<install>\build\Logs\log_<date>_<version>\` with files `"<stamp> application_000.log"` and `"<stamp> push-notifications_000.log"` (older builds: `notifications.log`; `output.log` duplicates them, skip it). Line format `date time|version|level|category|message` + optional pretty JSON block ending with a `}` line.
- Events: `Session mode: Pve|Regular|PvpSeason`, `… ProfileId:<hex> AccountId:<n>`, `scene preset path:maps/x.bundle` (= GameMap.scenePath), `TRACE-NetworkGameCreate profileStatus: '… Location: Interchange, … shortId: …'` (Location = GameMap.nameId), `GameStarting:/GameStarted:`, `Got notification | UserMatchOver`, `Got notification | ChatMessageReceived` with `message.type` 10/11/12 = task started/failed/finished and `templateId` = `<taskId> <suffix>`; type 4 + templateId `5bdabfb886f7743e152e867e 0` = flea sale. Mode for a notification is taken from the application log's mode timeline at that time.
- Machine-specific paths and the owner's own numbers live in `CLAUDE.local.md` (gitignored). The BSG launcher settings file also holds an auth token: only its path fields are read. `userData/last-backfill.json` holds the last backfill summary (Electron on Windows does not pipe main-process console output).
- Licensing: patterns were learned from TarkovMonitor (GPL-3.0) but written independently; do not paste its code. Player level cannot be synced: `player.tarkov.dev` needs a Turnstile token bound to tarkov.dev; Dashboard shows a quest-XP lower bound instead.
- The template `.gitignore` ignores any `logs` folder; `electron/logs/` is un-ignored explicitly. Electron bundles must be CJS (`dist-electron/main.cjs`, `preload.cjs`) because package.json is `type: module`. The renderer uses HashRouter when `window.desktop` exists.

## Environment gotchas
- Bash tool: long multi-file heredocs (~10 KB+) fail to parse and write nothing; use the Write tool for source files. `$TMP` in Bash is the Windows temp folder, not the scratchpad.
- The Claude browser pane is often hidden: screenshots time out and animation frames/transitions don't run (map size caching, sidebar width). Verify with JS probes, set `resize_window` 1280×800 before measuring, reload after resizing. The HMR-cached `useMemo` results persist across module hot updates; reload to verify logic changes.
- npm 11 blocks install scripts for new packages; `npm install-scripts approve <pkg>` or run `node node_modules/electron/install.js` if the Electron binary is missing.

## Stash scanner (v1.2.0, 2026-10-04)
- `src/scan/core.ts` (pure, shared with Node): tarkov.dev `gridImageLink` images are exactly what the stash draws, so each item becomes an RGB fingerprint of `FP`=12 px per cell (area-averaged with `sampleRegion`). `detectGrid` finds the cell pitch/offset from edge-profile periodicity (any resolution; the owner's 1440p crop is 84 px). `scanGrid` compares every cell × footprint (incl. rotated, `rotateCW`) against same-footprint fingerprints, masking the bottom strip (counts, durability, FIR tick) and, for rotated items, the name strip; `emptyCells` builds an "empty slot" template from low-contrast cells and skips them; greedy non-overlap with a small per-cell bonus for larger footprints (`AREA_BONUS`). Errors: <12 sure, <18 likely, else check.
- Fingerprints: `npm run scan:fingerprints` → `public/scan/fingerprints.{json,bin}` (~5.9 MB, gitignored, presets skipped; grid images cached in `assets-src/scan/grid-cache`); CI builds them before tests. `npx tsx scripts/scan-test.ts <png>` writes `<png>.scan.png` with boxes. Test image: `assets-src/scan/junk-box.png` (owner's Junk box, 62/63 right; BrokenLCD's in-game background differs from its grid image).
- App: worker `scan.worker.ts` (Vite `worker.format: 'iife'` so it loads from file://), `scanner.ts` loads the data via `window.desktop.readAppResource` on desktop (Chromium cannot fetch file://) or fetch on web. `ScanDialog.tsx` (opened from Item Collection's "Scan screenshot" button, Ctrl+V there, or the desktop scan hotkey `scanHotkey`, default Alt+Shift+S, which captures the display under the cursor via `electron/capture.ts`). Also lists Documents\Escape from Tarkov\Screenshots. Rows group by item, default-tick items still needed, editable counts, "Wrong item?" (alternatives + search), Add vs Replace into `inventory.collected` (alternatives a quest accepts map to the need's canonical id). Stack counts are not read (ammo flagged "check amount"). v1.3.0: second background-free comparison on the item's own pixels (unrotated, icon ≥40% of pixels, +4 penalty) for tinted/highlighted slots; "Sure" also needs a 1.5 margin over the runner-up and "Check" rows start unticked; keep/sell per row (keep up to what is still needed, sell the rest with sellValue from lib/economy) and green/red tints per box.
- Learning (v1.4.0): "Wrong item?" saves the screenshot patch of each corrected spot (`src/scan/learned.ts`: fingerprint + small JPEG, IndexedDB key `tarkov-companion-scan-learned`, newest 4 per item+footprint, 400 max). Footprint = detected one if the chosen item has that size (or rotated), else the item's own size anchored at the cell (two wrong 1x1s that were one 1x2). Every scan passes them to the worker (`withLearned`), and they get `LEARNED_BONUS` 1.5; rows show "Learned". "Your corrections" panel (`LearnedPanel.tsx`): rescan, export/import JSON, forget. Shipping to everyone: put exported files in `scan-corrections/`; `npm run scan:fingerprints` appends them as `src: 'correction'` entries (also get the bonus); `npm run scan:check` uses them as test images (base-only vs leave-one-out mismatch counts).
- Learning model = nearest-neighbour memory (a trained net would need far more labelled data than one user has): kinds `correct` (fix, bonus 1.5), `confirmed` (uncertain match kept and applied, bonus 0.8), `not` (the wrong guess for that look; X is ruled out where the spot is closer to a rejected look than to X's picture, or within NOT_RADIUS 9). Fix = correct + not; Apply = confirmed for Likely rows. Same kinds ship via scan-corrections (src correction/confirmed/not). On the Junk box: one fix + apply took Sure from 36 to 48 (same screenshot, so optimistic).
- Grid: selections reuse the full screenshot's pitch (`hintPitch`), and grids of 48 cells or fewer run `refineGrid` (tries the strongest line offsets, keeps the alignment where 1x1 items match best) because item-name text can look like grid lines in small crops. maxP uses the longer image side / 3.
- v1.4.1 accuracy pass (owner's failed scan had cell 148 px instead of 84): `chooseGrid` lets line analysis only PROPOSE pitches (line-score peaks plus /2 and /3, min 36 px) and offsets; each proposal is judged by how well sampled non-empty cells match 1x1 fingerprints (better-half mean), then a coordinate-descent refinement (pitch ±1.2%, offsets ±4 px, sub-pixel) on a per-cell shortlist. Selections with a known pitch still use detectGrid(hint)+refineGrid. Size bonus capped (`AREA_BONUS_MAX` 2) and a big match with error ≥15 may not swallow confident smaller matches.
- OCR (`src/scan/ocr.ts`, tesseract.js, Apache-2.0, assets via `npm run ocr:assets` into gitignored `public/ocr`, CI runs it): bright lettering thresholded at 150 after a hand-written bicubic 2x upscale (canvas scaling blurred the text). Words → `nameLabels` (joined within one slot, right-aligned to the slot's right edge, top 40%) → items whose normalised short name (`normName`: 0→o, 1/i/|→l, 5→s) matches get pulled in and `NAME_BONUS` 10·(sim−0.5)·2; when someone matches a confident label (conf ≥50) the rest get `NAME_PENALTY` 12; weak reads (conf <40) need sim ≥0.9. Bottom-cut items are rescued from their visible rows when their name matches (`clipped`). Short names ship in fingerprints.json (`n`). Icons get redrawn by BSG (GPhone, Bulb, MCB differ from tarkov.dev's pictures), names don't, which is why this matters. Confidence: name-matched rows are Sure below error 20.
- Desktop serves `dist/ocr` and `dist/scan` read-only via the privileged `tcres://app/...` scheme (`electron/capture.ts resourceResponse`), because the page is file:// and Chromium cannot fetch() it. Web fetches use `cache: 'no-cache'`.
- Apply in the scan dialog works once per screenshot (`appliedRef` + state; re-scans and selections of the same image stay locked, a new image unlocks it), v1.4.4.
- v1.4.2 cell size per snip (owner: "not 1 snip is the same size"): `pitchFromWords` (OCR name height × 8.4 gives ±25%, the repeat of name right edges/tops every pitch gives the exact size; ≥2 names conf ≥45) narrows `chooseGrid` to ±3% when names were read; OCR images get a 24 px white margin (Tesseract missed text touching the border). `src/scan/cellSize.ts` remembers the pitch of the last scan with ≥4 and ≥60% Sure rows (localStorage `tc-scan-cell-size`); `chooseGrid(..., preferred)` fits a grid at that size too (offsets that leave room for one whole cell) and keeps it when its fit ≤ the fresh one (×1.5 when no names were read, since half-size grids fit narrow snips by chance). `scripts/scan-snip-test.ts` cuts random snips: same-screen snips 33/40 → 39/40 with the remembered size; mixed scales (wrong memory) stay ~32/40. Smoke test `TC_SCAN_IMAGE` takes comma-separated images (page reloaded between).
- v1.6.0 name anchors + box editor (owner: Hand drill 3x2 shown as two wrong 2x1s): a confident label (conf >= 50, >= 3 chars) within ANCHOR_MATCH 0.85 of a short name pins that item's top-right corner; scanGrid tries every matching item there (allowed over up to half "empty" cells: the drill's dark tip read as an empty slot, and items never cover empty slots) and adds NAME_PENALTY to boxes that contain a named slot anywhere but their top-right corner or with another item's name there. OCR words are now grouped into lines before joining ("Awl" 1 px higher slipped between "Hand" and "drill"), and a clean read is never glued to junk (conf < 40 next to >= 60, "FENA"+"Poster"). Box editor in ScanDialog ("Edit boxes"): tools Move/resize and Draw new box, grid lines, corner handles, snap to cells (src/scan/boxEdit.ts + tests); after an edit the worker's 'identify' message (identifyRegion on the last scan's image/grid/words/candidates) re-identifies just that box; boxes fully covered by the edited one are removed; picking an item in the strip saves a 'correct' learned record. Edited boxes live in `dets` (removed/edited flags; indexes stay = row spots). Test image assets-src/scan/junk-2.png (owner's Junk with the Hand drill).
- Dev tools: `scripts/scan-test.ts <png> [--no-ocr] [--pitch=]`, `scan-snip-test.ts [count] [--scale=] [--prior=] [--only=]`, `scan-compare.ts <png> <pitch> <ox> <oy>`, `scan-probe.ts <png> <row> <col> <w> <h> <normalizedName>`, `ocr-node.ts`. Test screenshots (gitignored) in `assets-src/scan/`: junk-box, junk-2, shot-1236, shot-124215, shot-124222, shot-124558 (the one that failed), small-crop.
- Versioning (owner's rule): new features bump the middle number (1.4 → 1.5.0); fixes bump the last (1.4.0 → 1.4.1).
- Safety (owner requires zero game interaction): no child processes (the registry lookup in the locator was removed in 1.3.0), the tcres:// scheme only serves the app's own scan/ and ocr/ files, no native modules, no injection/memory/input/packet access, logs opened read-only per poll, capture = desktopCapturer of the monitor on hotkey only, hotkeys via globalShortcut (RegisterHotKey).
